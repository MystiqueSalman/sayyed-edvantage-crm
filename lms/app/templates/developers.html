Authentication

All /api/v{{ version }} requests need an API key issued by an admin at Admin → API Keys. Send it as:

Authorization: Bearer <your-key>
# or
X-API-Key: <your-key>

Keys carry scopes — a key can only call endpoints whose scope it has. Error responses always use the envelope {"error": {"code": ..., "message": ...}}:

{"error": {"code": "insufficient_scope", "message": "Key lacks required scope(s): leads.write"}}

Rate limiting: per key (default 300 req/min). Exceeding it returns 429 with a Retry-After header.

Examples

List courses courses.read

curl -H "Authorization: Bearer $KEY" {{ base_url }}/api/v{{ version }}/courses

Create a lead leads.write

curl -X POST -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"name":"Priya Verma","phone":"+919876543210","email":"priya@example.com","course_id":1}' \
  {{ base_url }}/api/v{{ version }}/leads

Verify a certificate certificates.verify

curl -H "Authorization: Bearer $KEY" {{ base_url }}/api/v{{ version }}/certificates/verify/SE-ABC123XYZ

Webhooks

Register a URL at Admin → Webhooks and subscribe to events. Every delivery POSTs JSON:

{"event": "enrollment.created",
 "sent_at": "2026-09-28T04:30:00Z",
 "data": {"enrollment_id": 12, "user_id": 5, "course_title": "Data Science", ...}}

Signature: the X-SE-Signature header is the hex HMAC-SHA256 of the raw body with your webhook secret. Verify it:

import hmac, hashlib
sig = hmac.new(secret.encode(), request_body, hashlib.sha256).hexdigest()
assert hmac.compare_digest(sig, request.headers["X-SE-Signature"])

Failed deliveries retry 3× (backoff 1s → 2s → 4s); every attempt is logged under Admin → Webhooks → 📋 Deliveries.

🎬 Video Security — signed lesson URLs

Video lessons are served through short-lived, per-user signed URLs instead of raw embed links. The lesson page embeds /v/<token>; the watch page's player loads /v/<token>/stream, which 302-redirects to the stored video URL — the raw URL never appears in page source.

Token format: URL-safe base64 of <lesson_id>.<user_id>.<exp_unix>.<sig_hex>, where sig_hex = HMAC-SHA256(app SECRET_KEY, "<lesson_id>.<user_id>.<exp_unix>"). Tokens are bound to one lesson and one user — the watch route requires the logged-in user to equal the token's user, and the user must be enrolled in the course (or be staff).

Expiry: per-lesson VideoPolicy13.token_expiry_hours (editable at Manage course → lesson → Edit video policy, 1–72h); lessons without a policy use the p13_video_default_expiry_hours app setting (default 2h). The same editor toggles the download button on the watch page (hidden by default).

Rotation: changing the Flask SECRET_KEY instantly invalidates every outstanding token (signature verification fails); fresh URLs are minted on the next lesson-page render. No per-token revocation list is kept.
